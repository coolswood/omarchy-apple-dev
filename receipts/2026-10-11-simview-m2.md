# M2: a SwiftUI view renders to a PNG on Linux, CPU only

2026-10-11. `simview/` on branch `simview-m2`. The demo app
`sdk-free/swiftui/HelloApp.swift` compiles unchanged on Linux. It builds
against our own `SwiftUI` module. The app renders one frame to a 390 x 844
PNG. No GPU, no Mac, no phone. No Apple-derived material. The plan is rung M2
in `docs/IOS-SIMULATION-LINUX.md`.

## What was built

- `simview/Sources/SwiftUI/SwiftUI.swift` is our `SwiftUI` module. It
  declares the vocabulary the app uses: `App`, `Scene`, `View`,
  `WindowGroup`, `VStack`, `Text`, `Button`, `@State`, `HorizontalAlignment`,
  and the result builders. It also implements that vocabulary. Views build a
  render tree. A measure pass sizes the tree in points. A place and draw pass
  fills one RGBA buffer. One pixel is one point. `App.main()` parses `--out`,
  renders, and writes the PNG.
- The glyphs are a hand-drawn 5 x 7 bitmap font. The PNG encoder is ours. It
  has a CRC32 table and an Adler32. It writes a zlib header, stored deflate
  blocks of at most 65535 bytes, filter byte 0 per scanline, color type 6,
  and bit depth 8.
- `simview/build.sh` builds the module and the demo. The demo lands at
  `simview-demo` in the repo root. `simview/test.sh` runs the checks below.
  `simview/compare.py` states the golden tolerance: at most 0 differing
  pixels, every channel off by at most 0.

## Commands and outputs

Build host: a Linux x86_64 container. Swift 6.4 lives inside an Arch chroot.
The runner script binds this worktree at `/work`. The runner is a private
copy of the repo arch runner. Its worktree path was changed:

```sh
cp ~/tmp/apple-dev/archrun.sh ~/scratch/apple-dev/simview/archrun.sh
sed -i 's#^W=.*#W=$HOME/src/omarchy-apple-dev-wt-simview#' \
  ~/scratch/apple-dev/simview/archrun.sh
```

Build and render, with the wrapper exported:

```sh
$ export SIMVIEW_CHROOT_RUN=$HOME/scratch/apple-dev/simview/archrun.sh
$ bash simview/build.sh
built /work/simview-demo
$ $SIMVIEW_CHROOT_RUN --user '/work/simview-demo --out /work/simview/build/demo1.png'
wrote /work/simview/build/demo1.png 390x844
$ file simview/build/demo1.png
simview/build/demo1.png: PNG image data, 390 x 844, 8-bit/color RGBA, non-interlaced
```

The image: white background. The VStack sits centered in the screen with 16
points of spacing. `taps: 0` is black. The button label `tap me` is #007AFF.
I viewed the PNG and a zoom of the text block. Then I counted the drawn
pixels with PIL on the host:

```python
im = Image.open("simview/build/demo1.png").convert("RGBA")
print(sorted([x for x in im.getcolors(200000) if x[1] != (255,255,255,255)],
             reverse=True)[:5])
# [(74, (0, 0, 0, 255)), (68, (0, 122, 255, 255))]
```

The count: 74 black pixels for `taps: 0`. 68 blue pixels for `tap me`.
Everything else is white.

Full test run. It is the same block `tests/run.sh` calls:

```sh
$ bash simview/test.sh
built /work/simview-demo
== render twice, bytes must be identical
wrote /work/simview/build/demo1.png 390x844
wrote /work/simview/build/demo1-again.png 390x844
ok   identical bytes across two renders
== compare with golden (simview/compare.py states the tolerance)
```

The negative control copies `HelloApp.swift` with
`sed 's/count = 0/count = 3/'`. It rebuilds that copy against the same
module. Its render reads `taps: 3`. The golden compare fails on it, as the
test requires.

## Where the entry point lives

The demo has `@main struct HelloSwiftUIApp: App`. It has no other entry
point. The synthesized entry call resolves to `App.main()` in our module.
That method is the whole runtime for M2. It parses `--out`, renders
`Self().body`, writes the file, and exits 0. A missing `--out` prints usage
on stderr and exits 2.

## Not in this step

- No real SwiftUI layout, font shaping, animation, Metal, or GPU. The draw
  path is ours. It is not Apple's renderer.
- No touch input and no state writes. The module renders once with the
  initial state. Button actions are stored. They never fire. M3 adds the
  frame format and the state to render loop. See `docs/SIM-INPUT-MODEL.md`.
